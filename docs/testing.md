# Лабораторная работа №7 — автоматическое тестирование

## Среда

Тестирование запускается локально и в GitHub Actions из файла `.github/workflows/ci.yml`.

- Go: стандартный пакет `testing` и `net/http/httptest`.
- Контракты: отдельный Go-модуль `contracts`.
- Интеграция: Bash, Docker Compose, PostgreSQL, RabbitMQ, InfluxDB и тестовые HTTP-сервисы.
- Web UI: ESLint, сборка Vite, интеграционная проверка доступности страницы и API.

## Проверяемые требования

| Функция | Проверка |
|---|---|
| API: состояние и последняя проверка | HTTP unit-тесты, проверка ошибок 404/502, интеграционный сценарий |
| Проверка доступности HTTP-сервиса | Unit-тесты Checker (успешные, ошибочные, граничные статусы, тайм-ауты) |
| Периодическая проверка | Unit-тесты Scheduler и интеграционный сценарий |
| Обработка конфигурации | Unit-тесты, проверки обновления и устаревших версий в Docker |
| Надёжная обработка сообщений | Проверки повторной доставки, нескольких Checker и DLQ |
| Сохранение и чтение метрик | Unit-тесты хранилища и gRPC; интеграционная проверка через API |
| Web UI: показ последнего результата | Сборка, линтер, доступность веб-страницы через Docker |

Сейчас не реализованы управление сервисами через Web UI, аутентификация,
история, аналитика и работающие уведомления. Их функциональное тестирование
невозможно до появления соответствующих функций. Формальная проверка
заготовки Notification Service не считается проверкой отправки уведомлений.

## Локальный запуск

```bash
go test ./contracts/... ./services/api/... ./services/checker/... ./services/metrics/... ./services/notification/... ./services/scheduler/...
cd web && npm ci && npm run lint && npm run build && cd ..
bash scripts/integration-test.sh
bash scripts/prototype-test.sh
bash scripts/monitoring-core-test.sh
```

Для интеграционных сценариев необходим запущенный Docker.

## Отчёты

Этап `Go quality` запускает `go test -json`, сохраняет JSON и автоматически
конвертирует его в JUnit XML. Сводка появляется в GitHub Actions Job Summary,
а подробные результаты доступны в артефакте `go-test-results`.
Профили покрытия Go сохраняются отдельно в `go-coverage`.

Этап `Quality metrics` сохраняет `quality-metrics`: сводку покрытия,
количество пройденных и неудачных тестов, длительность тестов,
максимальную цикломатическую сложность, размер коммита и время CI.

Значение покрытия относится только к включённым в измерение Go-модулям,
а не к Web UI или всей функциональности системы. Наличие теста не
означает, что функциональность полностью проверена.

## Доказательства для отчёта

Для защиты следует сохранить скриншот успешного запуска GitHub Actions,
сводки Go-тестов, загруженных артефактов и результатов интеграционных
сценариев. Числа успешно выполненных тестов и покрытие нужно брать из
конкретного запуска CI, а не записывать предположительно.
